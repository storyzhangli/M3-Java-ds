## 4. 漏召回与数量不足

| 现象 | 实测证据 | 原因 |
| --- | --- | --- |
| Top-K=50 时实际只返回 4 条 | `retrieval-test-console.txt`：`TopK 边界通过: top1=1 top50=4` | `similarityThreshold=0.0` 对应 SQL 条件 `distance < 1`，等价只保留余弦相似度 > 0 的向量；与查询正交（相似度 0）或反向（相似度为负）的向量被过滤 |
| 10 题每题都能返回 5 条 | 每题 `hitCount=5` | 每题的查询与 8 个 chunk 中至少 5 个存在正相似度 |
| 无"零命中"题 | 10/10 | 语料量小（8 chunk），且均为设备故障同主题文本，词汇天然重叠 |

结论：本迭代的阈值 0.0 是"接受全部正向语义"的宽松策略，**不是"召回全部行"**。若业务需要"必定返回 K 条"，需要显式把阈值设为允许负相似度的值（框架阈值下界为 0，SQL 侧 `distance < 1`），或改为不设阈值只靠 `LIMIT K`；这属于下一轮阈值策略标定的内容，本迭代不做静默改动。

## 5. 根因归类

1. **模型语义能力**（首要）：本地 `LocalHashNgramEmbeddingModel` 是确定性字符 n-gram 哈希向量，只反映字面重合，无法处理同义表述（如"液位不足"vs"液位低于下刻线"）、语序变化和跨句指代。因此分数普遍偏低、排序易倒挂。
2. **Chunk 粒度**：C01 一个 chunk 同时承载"过热报警处置 + 冷却液补充 + 散热器滤网"三类信息，导致它被多个不同问题同时召回；按小节/语义边界切分可降低互相干扰。
3. **通用词干扰**：SERVO-C03 含"工单/备注/系统提示词"等跨领域高频词，在缺乏语义理解时容易被任意设备类问题召回。
4. **阈值策略**：0.0 阈值接受弱相关的正分结果，使"低分噪声"进入 Top-5（本次 Top5 最低分可低至 0.013438）。

## 6. 改进方向（不作为本次交付内容）

| 方向 | 说明 | 影响的验收口径 |
| --- | --- | --- |
| 换真实 embedding 模型 | 接入 bge-m3 / text-embedding-3-small 等语义模型，替换本地 hash 模型（`EmbeddingModel` 接口不变，`vectorSpaceId` 会变化，需要重建向量） | 分数分布与排序会显著改善，需重跑 10 题评估 |
| 混合检索 + 重排序 | 关键词检索（已有 `KnowledgeRetrievalService`）与向量检索并行召回后做 RRF / Cross-Encoder 重排 | 提升 hit@1，但增加延迟与依赖 |
| 阈值标定 | 基于人工标注结果，按业务可接受噪声率确定 `app.retrieval.similarity-threshold` | 决定"Top-5 是否总能满 5 条" |
| Chunk 重构 | 按小节切分、控制单 chunk 主题单一 | 降低跨题干扰 |
| 人工标注闭环 | 由业务方对 50 条候选逐条标注，产出 hit@1 / hit@5 / 噪声率 | Level 5 的最终依据 |
