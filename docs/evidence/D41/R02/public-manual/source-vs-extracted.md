### #13 不匹配根因（已定位为源文件缺陷，非 R02 算法缺陷）

- 该 PDF 为 Danfoss 官方 Ghostscript 压缩重制版，页 71 所用子集字体 `JDPEEV+ArialMT` **缺 ToUnicode 映射**（stderr 日志有 `No Unicode mapping for 54 (82)` 等告警），文本层本身把 6 输出成 8。
- 证据链：`public-manual-verification.log` 中 `No Unicode mapping for 54 (82)` 等 WARN 行＋原页渲染图 685 对比文本层 885。
- 分桶修复（R02-02）只处置"同一文本 run 的列归属"，不改动 run 内容；`885` 作为值原样入列，行为正确。**若引入 Tabula/Camelot 也读同一文本层，结果相同**——此项属"真实文档文本层质量"边界，如实记录为 NOT FIXED（超出本任务允许手段：禁 OCR/新框架）。
