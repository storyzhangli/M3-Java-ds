## 6. documentId 规则

- 由服务端生成。
- UUID 去横线，32 字符。
- 客户端不能指定或修改。
- 创建后稳定关联元数据和文件内容。

## 7. 文档登记

入口：

```text
POST /api/v1/knowledge/documents
Content-Type: application/json
```

请求：

```json
{
  "source": "equipment_manual",
  "title": "设备维护手册",
  "version": "1.0"
}
```

服务端：

- 校验 source/title/version。
- 生成 documentId。
- status=PENDING。
- 只写元数据，不读文件、不计算 hash。
- 返回统一 Result。

## 8. 文件导入

入口：

```text
POST /api/v1/knowledge/documents/{documentId}/import
Content-Type: multipart/form-data
file=<file>
```

流程：

```text
查找文档
 -> 基础检查（文件存在、非空、大小、扩展名、读取）
 -> SHA-256
 -> 重复预检查
 -> 原子抢占 PROCESSING
 -> Tika/MIME/UTF-8/解析
 -> COMPLETED 或 FAILED
```

Controller 只负责 multipart 接收和 Result 包装，业务在 Service。

## 9. 职责分离

登记：

- 业务元数据。
- 文档身份。
- 初始状态。

导入：

- 文件字节。
- 内容 hash。
- MIME/编码/解析。
- 文件元数据与解析文本关联。
- 状态变更。

这样可以先建档后补文件，也不会让文件上传入口创建重复的元数据语义。

## 10. 状态流转

```text
PENDING
  -> PROCESSING
  -> COMPLETED
  -> FAILED
```

触发：

- PENDING：登记成功。
- PROCESSING：导入通过基础读取并原子抢占成功后。
- COMPLETED：MIME/编码/基础解析和内容写入成功。
- FAILED：基础读取、文件校验、MIME/编码或解析失败。

细节：

- PROCESSING 不允许并发重入。
- FAILED 允许重新上传重试。
- COMPLETED 相同 hash 重复上传为幂等返回。
- COMPLETED 不同 hash 返回状态冲突，不覆盖原文件。
- 容器层 multipart 超限发生在 Controller 前，文档保持 PENDING，客户可缩小文件后重试。

## 11. 文件安全校验

### 两层大小限制

1. Spring:

```yaml
spring.servlet.multipart.max-file-size
spring.servlet.multipart.max-request-size
```

2. 业务：

```yaml
app.knowledge.import.max-file-size
```

两者都使用服务端配置，业务层可防止直接调用 Service 绕过 Multipart。

### MIME 与扩展名

- 扩展名白名单：txt/md/markdown/html/htm/pdf。
- 实际 MIME 由 Tika 根据内容检测。
- 扩展名与实际 MIME 必须匹配。
- 前端 Content-Type 不作为可信结论。
- 伪装成 txt 的 PNG 被拒绝。

### 编码

- 文本类型使用严格 UTF-8 `REPORT` 解码。
- 非法字节和 NUL 字符被拒绝。

### 解析

- HTML/PDF 使用 Tika/PDFBox。
- 解析文本为空或超过字符上限失败。

## 12. contentHash 重复策略

- 原始文件字节 SHA-256。
- 不使用文件名。
- DB:

```sql
UNIQUE KEY uk_knowledge_content_hash (content_hash)
```

业务策略：

- 不同文档相同 hash：返回 4092，后导入文档保持原状态，不进入 PROCESSING。
- 原文档状态/version/updatedAt 不改变。
- 同一 COMPLETED 文档相同 hash：幂等返回，updatedAt 不改变。
- 并发重复：唯一约束兜底，一个成功、一个识别为重复；只存在一个非空 hash。

## 13. 异常映射

| 业务码 | 含义 |
|---:|---|
| 4001 | 登记参数校验失败 |
| 4041 | 文档不存在 |
| 4091 | 状态冲突/正在处理/已完成不可替换 |
| 4092 | 内容重复 |
| 4101 | 文件不合法、超限、编码/读取失败 |
| 4221 | 基础解析失败 |

接口仍使用 HTTP 200 + `Result{code,msg,data}`。

底层异常不直接回显。服务端记录异常类型，FAILED 只保存安全错误码和提示。

## 14. 事务与一致性

事务边界：

- 登记：插入 PENDING。
- Claim：条件更新 PENDING/FAILED -> PROCESSING，写文件字节。
- Complete：条件更新 PROCESSING -> COMPLETED，写解析文本。
- Fail：PENDING/PROCESSING/FAILED -> FAILED，写安全错误。

解析在事务外，避免长时间持有数据库连接。

更新时间使用 `DATETIME(6)`，保证状态变更时间可区分。
