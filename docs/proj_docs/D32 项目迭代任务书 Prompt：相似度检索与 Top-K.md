## 4. 核心实施需求

### 4.1 Query Embedding

实现用户问题的向量化：

1. 接收用户查询文本。
2. 使用 D31 相同的 EmbeddingModel。
3. 生成 384 维查询向量。
4. 校验空文本、向量非空、维度及数值合法性。
5. 保证查询向量与入库向量属于相同模型及向量空间。

不得另建 Embedding 模型，不得混用不同维度或不同模型版本的向量。

### 4.2 Top-K 相似度检索

使用 Spring AI 1.1.8 的 `VectorStore` 相似度检索能力。

要求：

- 默认 Top-K = 5。
- 支持根据实际接口设计调整 Top-K，但必须进行合理参数校验。
- 使用 COSINE 距离度量。
- 检索结果来自 PostgreSQL + pgvector。
- 返回 Chunk 内容、来源信息和必要元数据。
- 尽可能保留检索分数及其原始语义。

必须核对 Spring AI 返回分数的含义：如果 API 返回的是 similarity score，不得误称为 distance；如果底层返回 cosine distance，也不得直接当作 similarity。

不得自行编造、归一化或伪造相似度分数。

如果当前适配器无法返回分数，明确记录能力限制，不得通过虚构字段补齐。

### 4.3 来源信息与元数据过滤

根据现有 D31 数据结构返回真实来源信息，例如：

- documentId。
- documentVersion。
- chunkId。
- 原始文件名或来源标识。
- 页码或其他已有定位信息。

只返回代码和数据库中真实存在的字段。

检查现有 metadata 结构，验证 Spring AI 过滤表达式能否支持实际字段过滤。

至少选择一项真实存在且有业务意义的元数据进行过滤验证。

要求：

- 过滤条件与实际 metadata 对应。
- 不得虚构 metadata 字段。
- 不得因过滤条件错误导致静默返回错误结果。
- 明确过滤前后的检索结果差异。

如果现有 metadata 不足以支持某种过滤需求，记录缺口和后续改进建议，不得擅自扩大本次数据模型范围。

### 4.4 检索接口与结果结构

根据现有工程风格提供必要的检索服务和接口。

建议返回：

- 原始查询文本。
- Top-K 参数。
- 检索到的 Chunk 内容。
- 来源信息。
- 元数据。
- 可用的相似度分数。
- 检索耗时。

保持职责清晰：

1. Query Embedding：负责查询向量生成。
2. Retrieval Service：负责向量检索。
3. Result Adapter：负责结果映射和来源信息整理。
4. Controller：负责请求参数和响应。

优先复用已有统一返回、异常处理、日志和 TraceId 规范。

本次只实现检索能力，不生成大模型答案，不接入完整 RAG 问答链。

## 5. 真实业务问题评估

至少准备 **10 个真实业务问题**，使用当前知识库实际文档进行检索。

问题应覆盖不同设备、故障现象、故障原因、维修方法或业务场景，具体内容必须根据实际知识库编写，不能凭空假设知识库包含某些资料。

每个问题执行 Top-5 检索，并逐条人工标注结果是否相关。

建议建立评估记录：

| 问题   | Top-5 实际结果 | 相关片段 | 噪声 | 漏召回 | 备注     |
| ------ | -------------- | -------- | ---- | ------ | -------- |
| Q1     | 实际记录       | 人工标注 | 记录 | 记录   | 原因分析 |
| Q2–Q10 | 同上           | 同上     | 同上 | 同上   | 同上     |

评估要求：

1. 记录每个问题的实际查询文本。
2. 保存真实返回的 Top-5 结果。
3. 记录每条结果的来源、Chunk ID 和实际分数（如果支持）。
4. 人工标注每条结果相关或不相关。
5. 记录检索噪声。
6. 记录应该召回但未召回的相关片段。
7. 分析问题表达、Chunk 切分、Embedding 模型、元数据过滤和知识库内容等可能原因。

**人工标注必须由用户或明确参与评估的人完成。AI 可以提供初步判断和分析，但不得把 AI 自动判断冒充人工标注。**

如果无法确定某条结果是否相关，标记为待确认，不得强行标注。

## 6. 检索评估与阈值策略

本次不盲目设置相似度阈值。

先收集至少 10 个问题的实际检索结果和分数分布，再分析：

- 噪声结果比例。
- 相关片段漏召回情况。
- 不同问题的分数分布。
- 相关与不相关结果的分数重叠情况。
- 不同 Chunk 和问题表达对检索结果的影响。

可以根据真实标注计算适用的 Precision@5、Recall@5 等指标，但必须明确相关文档集合和标注依据。

本次交付重点是建立评估基线，而不是追求未经验证的阈值或指标。
