## 二、脚本设计要点（为什么这样写）

1. **聚合哈希（freeze-scan.ps1）**：`Ordinal` 排序（非文化敏感）+ `relPath\n+sha256` 拼接再哈希——
   任何文件增删改/重命名都会破坏聚合值；`[Array]::Sort+Comparison` 替代 `Sort-Object`
   （后者 `-Culture` 参数不吃 `StringComparer`）。
2. **语义 diff（semantic-diff.ps1 v2）**：三分类=白名单键（elapsedMs 等计时）→TIMING；
   `map43to44` 显式命名等值映射命中→NAMING_EQUIV（**不静默**，每处计数落报告）；其余逐值对比→
   SEMANTIC/STRUCT 计数。**教训**：首版用正则打补丁把脚本自己弄污（`$jitter$jitter`）——
   判定类脚本宁可整文件重写，不打增量补丁。
3. **V1 双标注口径**：mock 装配（hash-ngram + relevant-score 0.0/0.15 边界）下可答题终态
   CLARIFY/REFUSE 零引用=非编造安全态；"引用必须真"的实证链=IT 轮 S05/S06/S08 +
   CitationExistenceValidator 11 单测。**活体可答题必须用 key sentence 原文**——自造自然语言
   题会被证据充分性评估拒绝（LOW_RELEVANCE），那是护栏正确动作而非缺陷。
4. **泄漏判定必须 hits 级**（V3-③）：响应 `data.query` 回显请求原文，全文正则必假阳性
   （与 D43 BC-15 同构，二次踩坑坐实 O-15 模板化必要）。
5. **表结构指纹用 information_schema ASCII 文本化**，不用 SHOW CREATE——中文注释经控制台
   编码回读乱码，指纹不稳定。

## 四、可迁移的工程判断法

1. **里程碑轮的"零改动"不是不动，是改动全走登记通道**：BC-21 属环境 DDL（有修复文件+复验），
   BC-22 属主码（有约束→不修→O-07 升级），演示页属任务书明示白名单——三类改动三种留痕形态。
2. **双口径回归先行**：R-A/R-B 在任何写面之前跑，能把"环境回归类失败"（如 BC-21 的前置写面）
   与"代码语义失败"分离，省一轮定位。
3. **专项 FAIL 先定界再定性**：本轮 V1/V2/V3 首跑 FAIL 全是测试侧——定界动作固定三件
   （响应实况全文、DB 侧权威计数、IT 同口径对照），**10 分钟内可把"被测面/判定面"分开**。
4. 熔断纪律实测有效：同根因 2 次熔断线未触碰；重启预算 4 次恰好用于 R-C/R-D/R-E/冒烟四实例，
   无一次浪费在盲目重试上。
