## 三、本次功能需求

### 1. PDF 解析能力

基于 D27 已有的文档登记与导入能力，增加 PDF 文档解析。

要求：

1. 检查现有文档导入 Service、Document 模型及文件存储方式。
2. 复用已有文档导入入口，不重复建设上传体系。
3. 识别 PDF 文件并调用对应解析器。
4. 提取 PDF 中的文本内容。
5. 尽可能保留原始页面边界及页码信息。
6. 将解析结果与 documentId 建立关联。
7. 保留文档来源、标题、版本等已有元数据。
8. 记录解析状态、更新时间及必要的异常信息。
9. 解析失败时能够正确反馈，不得伪造成功结果。

明确以下职责：

- 原始文件负责保留原始文档。
- 解析器负责提取文档内容。
- 解析结果负责保存提取文本及来源定位信息。
- 文档元数据负责记录文档身份与来源信息。

不得将原始 PDF 与提取文本混为同一个数据对象。

### 2. PDF 来源定位与元数据

本轮必须重点实现来源定位能力。

要求：

- documentId：关联原始知识文档。
- source：保留原始文档来源。
- title：保留文档标题。
- version：保留文档版本。
- pageNumber：记录提取文本所属的 PDF 页码。
- content：保存对应页面或页面片段的提取文本。
- updatedAt：记录相关数据更新时间。

根据现有 Schema 和项目架构决定具体字段及存储结构，不得擅自重复建设字段体系。

重点检查：

1. 提取文本是否能够追溯到原始 documentId。
2. 提取文本是否能够定位到原始 PDF 页码。
3. 多页 PDF 是否正确保留页面边界。
4. 空白页是否被错误地合并或丢失。
5. 页码是否与 PDF 实际页面顺序一致。
6. 多个页面的文本是否发生错误拼接。
7. 文档版本变化后是否能够区分不同版本的来源。

特别注意：

- PDF 实际页码与 PDF 阅读器显示的页码可能存在差异。
- 当前阶段优先使用 PDF 物理页面序号作为定位依据。
- 页码统一采用从 1 开始的页面序号。
- 如果原文存在印刷页码，应与物理页码明确区分，不能混用。
- 不得仅记录整份 PDF 的文本而丢失页面来源信息。

### 3. PDF 解析器与依赖版本兼容性

必须先检查项目当前技术环境，再选择 PDF 解析器。

要求：

1. 扫描所有相关 `pom.xml`。
2. 确认 JDK、Spring Boot、Maven 及已有依赖版本。
3. 检查是否已经存在 PDF 解析相关依赖。
4. 优先复用项目已有且兼容的解析能力。
5. 如果需要新增解析器，先验证其版本与当前环境兼容。
6. 明确新增依赖的用途及传递依赖影响。
7. 避免引入不必要的重复解析库。
8. 避免未经验证直接升级 Spring Boot 或其他基础依赖。

如果选择 Apache PDFBox 或其他 PDF 解析器，必须以项目实际兼容性验证结果为准，不能默认使用最新版。

必须确认：

- Maven 依赖解析成功。
- Java 编译通过。
- PDF 解析 API 与实际依赖版本一致。
- 不存在明显的依赖冲突。
- 测试环境能够真实运行解析器。

**禁止根据其他版本的 API 文档编写当前项目无法编译的代码。**

### 4. Word 解析：可选扩展

实施前检查：

- 项目是否已有 Word 解析依赖。
- 是否已经存在统一文档解析接口。
- PDF 与 Word 是否适合复用相同的解析结果结构。

### 5. 解析结果与原始文档的关联

要求建立清晰的数据关联：

`KnowledgeDocument → Original File → Parser → Extracted Content`

每份解析结果必须能够追溯到对应原始文档。

需要明确：

- documentId 的关联方式。
- 原始文件的保存位置及读取方式。
- 解析结果的存储方式。
- 页面序号的记录方式。
- 多页文本的组织方式。
- 解析失败时的状态及异常记录。
- 文档重新导入或重新解析时的数据更新策略。

如果现有系统已经有解析结果存储结构，优先复用。

如果需要新增数据结构，遵循最小必要原则，并说明设计原因。

## 四、原文与提取文本质量抽查

本轮必须进行真实文档解析验证，不能只通过 Mock 测试证明解析器可用。

至少选择一份可公开获取、具有明确来源的 PDF 设备手册或技术文档。

记录：

- 原始文档名称。
- 原始文档来源。
- 文档版本（如果能够确认）。
- 文件大小。
- PDF 总页数。
- 解析器名称及版本。
- 实际解析结果。
- 原文抽查位置。
- 提取文本抽查结果。

重点抽查：

1. 首页文本是否正确。
2. 普通正文页面是否正确。
3. 包含标题、段落和列表的页面是否正确。
4. 不同页面的文本是否正确分离。
5. 页码是否正确。
6. 空白页面是否正确处理。
7. 中文、英文及数字是否能够正常提取。
8. 特殊字符是否出现明显乱码或丢失。
9. 文本提取顺序是否与原文阅读顺序基本一致。

对于表格、复杂排版、多栏布局和扫描件：

- 明确解析器能够处理的范围。
- 记录实际观察到的问题。
- 不得将文本提取成功等同于版面结构完整。
- 不得假设普通 PDF 文本解析能够自动完成 OCR。
- 对无法提取文本的扫描件，明确标注需要 OCR 能力，暂不强制实现 OCR。

建立原文与提取文本的抽查记录，至少保留页面序号、原文观察结果、提取结果及差异说明。
