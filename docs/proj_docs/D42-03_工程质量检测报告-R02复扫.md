## 2. 定向疑点审查（4 项全部排除，附代码证据）

1. **远程响应负 index 逃逸？** 否——`parse()` 条件为 `idx==null || idx<0 || idx>=candidateCount || !seen.add(idx)` → INVALID_REMOTE_IDS 完整覆盖负值/越界/重复。
2. **每次调用新建线程池？** 否——`executor` 为构造注入的共享 cached pool，线程工厂设 `setDaemon(true)` + 命名 d42-rerank-call，超时路径 `fut.cancel(true)`，JVM 退出不受阻。
3. **LocalLexical `Math.min(topN,size)` 与"topN>候选抛异常"契约矛盾？** 否——RerankRequest compact ctor 先保证 topN≤size，min 为恒等防御，不改变语义。
4. **content=null NPE？** 否——`KeywordTokenizer.tokenCounts(null)` 返回空 map → lexical=0，按 cosine/rank 键继续排序。

### P2（记录、不整改，附理由）

| # | 事项 | 评估 | 建议 |
|---|---|---|---|
| P2-1 | RerankController 硬编码 topK/topN 上限 5/50，未走 `properties.maxCandidates()/topN()` | 冻结参数下行为一致；配置被覆盖时漂移方向是 **fail-safe 更严**，无越权风险 | R03 起改用 properties，避免双源 |
| P2-2 | `fut.cancel(true)` 无法真正中断 SDK 底层 HTTP IO（CompletableFuture 无中断语义），worker 持线程至调用自然结束 | daemon + 共享 cached pool 可复用，最坏占 1 线程×SDK 内部超时；结果已正确丢弃、台账 elapsed 记录的是预算值 | 授权远程轮观察线程水位后再决定包装 RequestConfig |
| P2-3 | timeout 单测 60ms 预算 vs stub 400ms sleep | 余量 6.7 倍，flaky 风险低 | 保留 |
| P2-4 | RerankCallLedger 类级 synchronized | 评估场景 QPS 极低（90 run 串行），锁无竞争 | 高频接入前改单线程 executor 异步落账 |
