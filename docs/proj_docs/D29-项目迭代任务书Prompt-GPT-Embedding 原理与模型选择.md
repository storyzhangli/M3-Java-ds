### 3. Embedding 调用组件

建立独立的 Embedding 调用能力。

要求：

- 接收 D29 生成的 Chunk 文本。
- 调用选定的 EmbeddingModel。
- 获取向量结果。
- 返回向量及必要的模型元数据。
- 明确处理空文本。
- 明确处理异常响应。
- 验证向量维度。
- 验证向量数值有效性。
- 避免将模型调用逻辑直接写入 Controller。

组件职责尽量分离：

- Embedding 配置管理。
- Embedding 模型调用。
- 向量结果校验。
- 模型元数据管理。
- 异常处理。

优先复用 Spring AI 现有抽象接口，避免无必要地重复封装底层 HTTP 客户端。

### 4. 向量维度与结果校验

必须验证 Embedding 输出向量的基本正确性。

要求：

1. 同一个模型配置下，相同文本多次调用，输出维度保持一致。
2. 不同文本能够正常生成对应向量。
3. 输出向量维度与模型配置一致。
4. 不允许返回空向量。
5. 不允许出现 NaN、Infinity 等非法数值。
6. 对异常或不完整响应进行正确处理。
7. 明确向量的数据类型及存储要求。
8. 记录模型名称和维度。

重点区分：

- 向量维度一致。
- 向量数值有效。
- 向量语义空间兼容。

这三个概念不能混为一谈。

特别注意：

两个不同模型即使都输出 1024 维向量，也不能据此认定它们的向量可以混合检索。

向量维度相同不等于向量语义空间相同。

### 5. 空文本与异常处理

必须建立明确的输入校验及异常处理策略。

至少覆盖：

- null 输入。
- 空字符串。
- 仅包含空白字符。
- 超过模型最大输入长度的文本。
- 模型接口超时。
- API Key 无效。
- 服务端限流。
- 模型服务暂时不可用。
- 返回数据为空。
- 返回向量维度异常。
- 返回向量包含非法数值。

要求：

- 空文本默认拒绝或跳过，不得生成无意义向量。
- 明确超长文本处理策略。
- 不得未经设计直接截断文本并丢失来源信息。
- 不得将模型服务异常当作正常业务结果。
- 记录必要的异常类型及错误信息。
- 日志中不得输出 API Key 或其他敏感信息。

### 6. 失败重试机制

验证模型调用失败时的重试行为。

要求：

1. 区分临时性故障与永久性错误。
2. 对超时、限流和部分服务端错误考虑有限重试。
3. 对无效 API Key、非法请求和不支持的模型等错误，不进行无意义的重复重试。
4. 设置最大重试次数。
5. 必要时采用指数退避。
6. 明确重试间隔和最大等待时间。
7. 避免无限重试。
8. 记录每次失败和最终执行结果。
9. 避免重试导致重复写入或重复索引。

如果采用 Spring AI 或底层 HTTP 客户端已有的重试机制，优先复用并验证其实际行为，不要重复叠加重试。

必须区分：

- Embedding 请求失败。
- 重试成功。
- 重试次数耗尽。
- 永久性错误直接失败。

至少管理：

- 模型名称。

- 最大输入长度。

要求：

2. 不得将真实 API Key 写入 Java 源码。
3. 不得将真实密钥提交到 Git。
4. 配置示例只能使用占位符。
5. 日志不得打印完整 API Key。
6. 文档不得记录真实密钥。
7. 明确开发、测试和生产环境的配置边界。
8. 支持在不修改业务代码的情况下切换模型配置。

如果项目已有迭代形成的模型配置体系，优先复用，不得另起一套重复配置体系。

### 8. 向量索引兼容性与模型切换

这是本轮重点验收内容。

建立明确的向量空间标识及索引兼容性管理规则。

建议记录：

| 元数据         | 说明                 |
| -------------- | -------------------- |
| provider       | 模型服务提供方       |
| modelName      | Embedding 模型名称   |
| modelVersion   | 模型版本或部署标识   |
| dimensions     | 向量维度             |
| vectorSpaceId  | 向量空间标识         |
| indexVersion   | 向量索引版本         |
| distanceMetric | 相似度或距离计算方式 |

要求：

1. 每批生成的向量必须能够追溯对应模型。
2. 明确当前索引使用的模型和向量维度。
3. 同一索引不得混入不兼容的向量。
4. 模型切换时执行兼容性检查。
5. 维度不同的向量禁止写入同一索引。
6. 模型不同且向量空间不兼容时禁止混合。
7. 维度相同不能作为兼容性判断的唯一依据。
8. 必要时通过独立索引或重新 Embedding 完成模型迁移。
9. 明确旧向量的保留、废弃和重新生成策略。

特别注意：

即使两个模型的输出维度相同，也可能使用不同的训练目标、向量空间和语义分布。

不得直接将模型 A 生成的向量与模型 B 生成的向量混合进行相似度检索。

本轮不要求建设完整的 VectorStore，但必须实现可验证的索引兼容性判断机制。

可以通过独立的兼容性校验组件、测试数据或必要的轻量索引元数据结构完成验证。

不得为了本轮测试提前建设完整的向量数据库体系。
