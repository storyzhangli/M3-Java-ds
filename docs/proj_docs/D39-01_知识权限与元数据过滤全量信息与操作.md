## 8. 踩坑记录（本轮全部实证，按杀伤力排序）

1. **PgVector 过滤器括号丢失（安全级）**：builder 裸 `b.or(...)` 不产生 Group → `PgVectorFilterExpressionConverter` 渲染 jsonpath 不加括号 → `A && B || C && D || E` 被 PG 解析为 `(A&&B) || (C&&D) || E`，设备哨兵段独立析取**恒真** → 跨部门/跨租户全泄漏。首跑矩阵 15 FAIL 全在此。类名是 `PgVectorFilterExpressionConverter`（非 PgFilterExpressionConverter）。修复=`b.group(b.or(...))`；教训：**凡下推谓词含 OR，单测必须走目标库真实 converter 渲染路径**——`PrintFilterExpressionConverter` 文本面与内存代数求值都抓不住（两者当时全绿仍漏）。
2. **DocumentChunker 生产 bug**：1-based chunkIndex 撞 0-based 校验 ⇒ HTTP vector-index 链从未可用（骨架期无任何端到端用例覆盖该链）。PG 存量 min(chunkIndex)=0 是改 0-based 的裁决证据。
3. **三层 schema 漂移**：MySQL document/page 列结构与全仓 14 模块 schema.sql+PO 契约不一致（HTTP 链才暴露，P0 探测不可见）；`created_at NOT NULL` 无默认在 MP 省略字段 INSERT 下炸 1364。处置均纯追加/纯放宽。
4. **ExecuteTwoDdl stdin 假执行**：args[3]="-" 时 DDL/DML **静默跳过**输出 DONE——首轮 DELETE 实际零操作。DML 一律文件参数；结果不确定先实查行数。
5. **D37 评测器 HTTP 探测硬编码 8080**：换端口 = BLOCKED。
6. **pgjdbc 42.1.4 不支持 PG18 SCRAM**（"不支持 10 认证类型"）：必须用项目 cp.txt 的新版驱动。
7. **PG `metadata ? 'x'` 与 JDBC 占位符冲突**（json `?` 操作符）：核验 SQL 用 `metadata->>'x' IS NOT NULL`。
8. **chat_session.session_id 是 32 位无连字符 hex**：按 uuid 正则提取外域集合恒空 → T4 断言空转；实扫 2431 行遗留会话才发现。断言设计前先做**格式实扫**。
9. **夹具 token json 是数组**（非 map）：`$toks.adminT1` 取值为 null → 全链 4001 假象；先读结构再写取值。
10. **矩阵 expectVisible 词面错配**（T1/T5/T6 三例口径 FAIL）：期望可见文档不含查询词面时必然 miss——正向对照改用「越权词面+自身词面 co-occurrence」。
11. **PS 里裸文本行**（`9090 alive: ...`）会炸解析；`Get-ChildItem -Filter` 不接受数组。
